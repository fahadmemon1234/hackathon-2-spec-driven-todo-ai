# Data Model: Advanced Task Management

**Feature**: Advanced Features, Event-Driven Architecture and Cloud Deployment
**Created**: 2026-01-19

## Entity: Task

### Fields
- **id** (Integer, Primary Key)
  - Unique identifier for the task
  - Auto-incremented integer

- **user_id** (String)
  - Identifier of the user who owns the task
  - Foreign key reference to user

- **title** (String, Required)
  - Title or name of the task
  - Maximum length: 255 characters

- **description** (String, Optional)
  - Detailed description of the task
  - Default: Empty string

- **completed** (Boolean)
  - Status indicating if the task is completed
  - Default: False

- **priority** (Enum)
  - Priority level of the task
  - Values: "low", "medium", "high", "urgent"
  - Default: "medium"

- **tags** (JSON Array)
  - Collection of string tags associated with the task
  - Default: Empty array []

- **due_date** (DateTime, Optional)
  - Date and time when the task should be completed
  - Default: NULL

- **is_recurring** (Boolean)
  - Indicates if the task repeats according to a recurrence rule
  - Default: False

- **recurrence_rule** (String, Optional)
  - Defines the pattern for recurring tasks
  - Format: iCalendar RRULE format (e.g., "FREQ=DAILY", "FREQ=WEEKLY;BYDAY=MO,WE")
  - Default: NULL

- **next_occurrence** (DateTime, Optional)
  - Date and time of the next instance of a recurring task
  - Calculated and managed by the system
  - Default: NULL

### Validation Rules
- title must not be empty
- priority must be one of the allowed values
- if is_recurring is True, recurrence_rule must be provided and valid
- due_date must be a valid future date if provided
- tags array must not exceed 20 tags
- each tag must be 50 characters or less

### State Transitions
- When completed is set to True:
  - If is_recurring is True, calculate and set next_occurrence based on recurrence_rule
  - If is_recurring is False, no special action needed
- When recurrence_rule is updated:
  - If is_recurring is True, recalculate next_occurrence
  - If is_recurring is False, next_occurrence remains NULL
- When due_date is set:
  - Schedule reminder event (typically 1 hour before due_date)

### Relationships
- Belongs to one User (many-to-one relationship)
- May have associated reminder events (one-to-many relationship)

### Indexes
- Primary Index: (id)
- User Priority Index: (user_id, priority) - for efficient priority filtering
- User Due Date Index: (user_id, due_date) - for efficient due date filtering
- User Recurring Index: (user_id, is_recurring) - for identifying recurring tasks
- Tags Index: GIN (tags) - for efficient tag-based queries

## Entity: User

### Fields
- **id** (String, Primary Key)
  - Unique identifier for the user
  - Generated by authentication system (Better Auth)

- **email** (String)
  - Email address of the user
  - Used for authentication and notifications

- **created_at** (DateTime)
  - Timestamp when the user account was created

- **updated_at** (DateTime)
  - Timestamp when the user account was last updated

### Relationships
- Has many Tasks (one-to-many relationship)

## Entity: Reminder Event

### Fields
- **id** (Integer, Primary Key)
  - Unique identifier for the reminder event
  - Auto-incremented integer

- **task_id** (Integer)
  - Reference to the task that needs a reminder
  - Foreign key to Task.id

- **user_id** (String)
  - Reference to the user who owns the task
  - For efficient user-based queries

- **title** (String)
  - Copy of the task title for the reminder

- **due_at** (DateTime)
  - The original due date/time of the task

- **remind_at** (DateTime)
  - When the reminder should be triggered (typically due_at - 1 hour)

- **sent** (Boolean)
  - Whether the reminder has been sent
  - Default: False

- **created_at** (DateTime)
  - When the reminder was scheduled

### Validation Rules
- remind_at must be before due_at
- task_id must reference an existing task
- user_id must match the user_id of the referenced task

### Indexes
- Primary Index: (id)
- Remind At Index: (remind_at) - for efficient scheduling queries
- Task Index: (task_id) - for task-based queries
- User Sent Index: (user_id, sent) - for user-based status queries

## Entity: Task Event

### Fields
- **id** (Integer, Primary Key)
  - Unique identifier for the event
  - Auto-incremented integer

- **event_type** (String)
  - Type of the event
  - Values: "created", "updated", "completed", "deleted"

- **task_id** (Integer)
  - Reference to the task that triggered the event

- **user_id** (String)
  - Reference to the user who owns the task

- **task_data** (JSON)
  - Complete snapshot of the task at the time of the event

- **timestamp** (DateTime)
  - When the event occurred

### Indexes
- Primary Index: (id)
- Event Type Index: (event_type) - for filtering by event type
- Task Index: (task_id) - for task-based queries
- User Timestamp Index: (user_id, timestamp) - for chronological user queries
